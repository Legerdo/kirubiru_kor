# 키루비루 웹 이식

제공된 한글판 건물부수기의 리소스와 정적으로 복원한 게임 로직을 사용합니다. 실행·리소스 준비·게임 로직 재생성·검증 모두 이 `web` 폴더 안에서 완결됩니다. 상위 원본 실행 파일과 폴더를 읽거나 실행하지 않습니다.

제공된 **13개 리플레이 모두 원본 저장 점수와 저장 최대 콤보가 일치**합니다. `replay11.rep`의 32,589,689점/75콤보도 재현됩니다. 원본 명령어에서 확인한 착지 비교 조건을 복원했으며, 기록 변경·점수 보정·무적 처리는 하지 않았습니다. 이 결과가 모든 입력과 원본 실행 화면의 완전 동등성을 보장하는 것은 아닙니다.

## 실행

[공개 웹 버전](https://legerdo.github.io/kirubiru_kor/)에서 바로 플레이할 수 있습니다.

이 폴더의 `run.bat`을 실행하거나 다음을 실행합니다. 기존 상위 `run-web.bat`도 사용할 수 있습니다.

```powershell
npm ci
npm run dev
```

주소: http://127.0.0.1:5298/ . 원본 `run.exe`를 실행할 필요가 없습니다. Node.js 22.12 이상 또는 24가 필요합니다. 이미 제공된 `public/game.wasm`으로 실행하므로 일반 실행/웹 빌드에는 Python, IDA, Zig가 필요하지 않습니다.

## 조작과 기능

- ← →: 원본의 세 위치 이동. 타이틀에서는 제1막/제2막/무제한 선택.
- ↑: 원본 준비 동작을 포함한 점프. ↓: 지상/공중 방어.
- Z: 베기, 메뉴 확인. X: 필살기.
- − / +: 볼륨 5% 조절. 숫자 키패드 − / +도 지원하며 0–100% 범위에서 저장됩니다. M: 음소거 전환. Ctrl/Command 조합의 브라우저 단축키는 가로채지 않습니다.
- 타이틀 ↓ Z: 점수표. 점수표 ← →: 모드 변경, ↑ ↓ Z: 기존 리플레이 선택/재생. 리플레이 Tab: 원본 빠르게 보기.
- P 또는 일시정지 버튼: 게임과 배경음·효과음을 함께 정지하며, 계속하면 멈춘 위치에서 재개합니다. 정지 중 볼륨/소리 버튼을 조절해도 음악은 재개되지 않습니다. Esc: 타이틀 복귀. 화면 이탈 시 키 입력을 해제하고 일시정지합니다.
- 상단 볼륨 0–100%: 배경음과 효과음에 즉시 적용하며 선택값을 브라우저에 저장합니다. 소리 켜기/끄기는 별도로 유지합니다. 마우스·터치 조절을 마치면 게임에 포커스가 돌아오며, 슬라이더에 포커스가 남아 있어도 Z/X/P/Esc가 동작합니다.
- 100% 기준 전체 출력 게인은 0.35입니다. 초기 버전 대비 약 9.1dB 낮추며, 배경음과 효과음의 상대 비율은 유지합니다.
- 터치 버튼과 일반 게임패드 입력을 지원합니다. 화면은 640×480 비율을 유지하며 창의 남은 높이·너비에 맞춰집니다. 조작법 9개는 넓은 화면의 오른쪽, 좁은 화면의 하단에 항상 표시합니다. 짧은 가로 창에서는 두 열로 배치합니다.
- 일시정지 상태는 게임 위의 어두운 배경과 중앙 문구로 표시합니다. 중앙 ‘계속하기’ 버튼을 클릭·터치하거나 Tab으로 이동해 Enter/Space로 누르면 게임과 음악이 재개되고 게임으로 포커스가 돌아옵니다. 저장 패널은 페이지 높이를 늘리지 않고 펼쳐집니다.

제공된 `save/game.sav`의 해금 단계 2를 그대로 가져오므로 제2막과 무제한을 바로 선택할 수 있습니다. 첫 실행은 원본 세이브의 복사본으로 시작하며 이후 점수/해금/리플레이는 브라우저 localStorage와 WASI 메모리 파일에 보관합니다. 원본 `save/`에는 쓰지 않습니다. 저장 내보내기/가져오기는 화면 하단에 있습니다.

## 구현과 검증

Phaser 3.90이 화면 크기, 프레임 루프, 캔버스 표시를 담당하고, WebAssembly가 원본 게임 규칙/태스크/보스/점수/리플레이를 계산합니다. 원본 60개 BMP 텍스처 ID, 공통 팔레트, 16개 WAV, MIDI 2개, 한국어 텍스트 2개, 세이브와 리플레이를 사용합니다. 자세한 근거와 한계는 [PORTING.md](PORTING.md)를 참고하세요.

```powershell
npm test                 # 입력/3개 모드/새 리플레이 재현/저장 파일 검증
npm run build            # 타입 검사와 dist/ 정적 웹 빌드
npm run verify           # 내장 리소스/복원 입력 해시와 원본 리플레이 13개 검증
npm run test:standalone  # 원본 없는 별도 복사본에서 로직 재생성/자산/테스트/검증/빌드/브라우저 실행
node tools/browser-replay-qa.mjs # 실제 웹 메뉴에서 replay11 선택, 정상 프레임 경로로 끝까지 재생/화면 확인
node tools/browser-qa.mjs # 실행 중인 로컬 서버에서 실제 브라우저 키보드/터치/음향/화면 확인
node tools/volume-qa.mjs  # 실제 출력 신호의 0% 무음, WAV/MIDI 공통 볼륨, 저장/포커스 회귀 확인
node tools/layout-qa.mjs  # 12개 화면 크기/회전, 스크롤·잘림 없음, 조작법 상시 표시와 일시정지 문구 확인
```

`dist/`는 정적 HTTP 서버에서 서비스할 수 있습니다. 더블클릭하는 `file://` 방식은 WebAssembly 및 리소스 로딩 때문에 지원하지 않습니다. 상위 [Pages 워크플로](../.github/workflows/pages.yml)는 `main`에 push할 때 테스트 → 원본 리소스/리플레이 검증 → 빌드 → GitHub Pages 배포를 수행합니다. CI는 보존된 `public/game.wasm`을 사용하므로 게임 로직 변경 시에는 아래 절차로 WASM을 재생성해 함께 커밋해야 합니다.

## 원본 로직 재빌드

정적 분석 결과는 `research/0x*.c`와 `.asm`, 실제 컴파일 입력은 `native/`, 재현 가능한 변환은 `tools/lift.py`에 있습니다. 복원 C는 저자의 원본 소스가 아니라 실행 파일에서 유도한 코드입니다. 초기 메모리 이미지와 코드 상수는 `research/initial-image.bin`, `research/reconstruction-inputs.json`에 원본 출처 해시와 함께 보존하며 재생성 전에 검증합니다. 원본 EXE나 IDA 없이 재빌드할 수 있습니다. 재빌드에는 Python과 Zig 0.13, 테스트에는 Node.js 24를 사용했습니다.

```powershell
python -m pip install --target .tools ziglang==0.13.0
npm run native
npm run assets
npm test
npm run verify
npm run build
```

`web` 폴더 전체를 보관하면 상위 `run.exe`, `image/`, `data/`, `sound/`, `save/` 없이 실행·수정·재빌드·검증이 가능합니다. `public/assets/`, `research/`, `native/`, `tools/`는 보존해야 합니다. `research/original-analysis.exe*`와 IDA DB는 추가 분석용이며 실행·재빌드에 필요하지 않습니다. 원본을 보유한 동안의 대조 감사는 `npm run verify -- --original-root ..`로 별도 수행할 수 있습니다. 원본 파일을 자동 삭제하지 않습니다.
